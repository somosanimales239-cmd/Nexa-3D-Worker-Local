NEXA 3D WORKER LOCAL 1.8.3 — STARTUP / QUEUE SYNC REPAIR

Confirmed problem in 1.8.2:
The website queues exact-8082 jobs under provider hunyuan3d_multiview_local, but an existing Worker installation could keep provider=stable_fast_3d in its persisted config. The Worker would then poll the stable queue while the Hunyuan job remained at 0%.

Additional confirmed config bug:
Hunyuan local root/python/cache/temp were added by the Hunyuan subclass, but the legacy ConfigStore save allow-list did not persist those new fields.

1.8.3 fixes only startup/connection/provider synchronization:
- one-time migration to hunyuan3d_multiview_local
- Hunyuan provider remains persistent after Save
- Hunyuan local paths remain persistent
- Start Worker performs a real Nexa heartbeat before reporting success
- missing Hunyuan root/Python produces an immediate visible error

IMPORTANT: scripts/hunyuan_multiview_worker.py is NOT changed by this repair. The 1.8.2 exact 8082 generation settings remain untouched.
